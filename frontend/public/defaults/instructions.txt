CV GENERATION INSTRUCTIONS


PURPOSE
Generate a professional, targeted CV using the Prompt CV MCP tools.


TOOLS
- get_cv_instructions — start session, returns sessionId + context + settings
- get_doc_content — read Google Docs (single ID or array)
- update_cv_data — deep-merge data into session; finalize=true to generate CV
- finalize_cv — generate CV from session data + template
- optimize_cv — adjust margins to fit target page count
- read_cv_context — read user's work history document
- update_cv_context — update user's work history document
- read_cv_instructions — read user's custom instructions
- update_cv_instructions — update user's custom instructions


WORKFLOW
1. Call get_cv_instructions → check the returned context
2. If context is empty or missing, STOP and do NOT proceed with CV generation:
   - Tell the user their work history document is empty
   - Offer 3 options:
     (a) Paste or attach an existing CV in the chat — you'll extract the information
     (b) Describe your experience here — you'll collect and organize it
     (c) Fill the context document directly in Google Docs
   - For options (a) and (b): extract/collect the information, then call update_cv_context to save it before doing anything else
   - For option (c): wait for the user to confirm they're done
   - Once the context document is updated, call get_cv_instructions again to restart with the full context
3. If user provides a job posting URL or doc ID, load it with get_doc_content
4. Process CV sections: experience → summary → skills → credentials
5. Send all data via update_cv_data with finalize=true and templateDocId from settings
6. If CV exceeds 2 pages, call optimize_cv
7. After generation, run the POST-GENERATION FEEDBACK flow below


TEMPLATE SCHEMA
The default template expects this data structure:

  header.name, header.title, header.location
  header.contact.phone, header.contact.email
  header.links.linkedin, header.links.github

  summary — 2-4 sentence professional summary

  experience[] — { company, location?, roles: [{ title, start, end, bullets[] }] }
  skills[] — { label, value } (e.g., { label: "Languages", value: "TypeScript, Python" })
  education[] — { school, degree, start, end }
  certifications[] — { name, issuer, issued?, expires?, credential_id? }
  training[] — { provider, program, type, start, end, focus }
  languages[] — string array (e.g., ["English (native)", "German (fluent)"])


CV RULES
- Reverse chronological order for experience
- Strong action verbs, quantified achievements (%, team size, users, revenue)
- 1-2 pages target, concise bullets (1-2 lines each)
- No first person ("Led..." not "I led...")
- Tailor to target role if specified
- If EU citizen, append "(EU Citizen)" to header.location


JOB ANALYSIS (stats)
Stats contain personal data and MUST NEVER be sent automatically.
Only include stats in the update_cv_data call if the user explicitly asks to track the application (e.g., "track this", "add to history", "save stats").

When the user opts in, use this format:

  stats: {
    jobTitle: "position at company",
    jobLink: "URL if available",
    matchEvaluation: "brief assessment of fit — strengths and gaps",
    rating: 0-10
  }

If the user has not explicitly requested tracking, do NOT include the stats field at all.


POST-GENERATION FEEDBACK
After the CV is generated and delivered to the user:

1. Ask if they have feedback on the result
2. Ask if they'd like the AI to update any of their source documents:
   - Work context document — to add new experience, correct facts, etc.
   - Instructions document — to refine generation preferences
3. If the user wants updates:
   a. Read the current document content first (read_cv_context or read_cv_instructions)
   b. Plan the changes — determine the most optimal way to incorporate the new information
   c. Check for conflicts between new content and existing content
   d. If conflicts exist, explain them to the user and ask how to resolve
   e. Apply the update (update_cv_context or update_cv_instructions)
4. If the user declines, end the session
